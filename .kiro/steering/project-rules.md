# プロジェクト固有ルール

## Build and Test ステージの必須記載事項

AI-DLCのBuild and Testステージで`build-and-test-summary.md`を生成する際、以下のセクションを必ず含めること。

### 残存脆弱性の詳細（Remaining Vulnerabilities Detail）

`npm audit`で脆弱性が残存している場合、以下を記載する：

1. **残存原因の概要** — なぜ修正できないのかを1〜2文で説明
2. **High脆弱性の一覧（表形式）** — パッケージ名、脆弱性概要、Advisory URL、残存原因
3. **Moderate脆弱性の一覧（表形式）** — パッケージ名、脆弱性概要、Advisory URL、残存原因
4. **なぜ修正できないのか** — 上流パッケージの未対応、内部依存のロック、間接依存の連鎖等を具体的に説明
5. **リスク判定** — 本番環境への影響、エンドユーザーへの影響、今後の対応方針

### テンプレート

```markdown
## Remaining Vulnerabilities Detail

### 残存原因の概要
[1〜2文で全体像を説明]

### High (X件)
| パッケージ | 脆弱性 | Advisory | 原因 |
|---|---|---|---|
| ... | ... | ... | ... |

### Moderate (X件)
| パッケージ | 脆弱性 | Advisory | 原因 |
|---|---|---|---|
| ... | ... | ... | ... |

### なぜ修正できないのか
| 原因 | 説明 |
|---|---|
| ... | ... |

### リスク判定
- **本番環境への影響**: [あり/なし — 理由]
- **エンドユーザーへの影響**: [あり/なし — 理由]
- **今後の対応**: [対応方針]
```
