**概要：** AWS Configを使用して、アカウントまたは組織全体にわたるすべてのリソースタイプを一覧表示する高度なクエリを実行し、廃止候補を特定します。AWS Config内に必須のタグ付けルールを設定して、非準拠リソースを自動的に検出し、リソース所有者向けの監査レポートを生成します。これらのデータを収集した後、FinOps実践者（FinOps Practitioner）はエンジニアリングチームと協力して、孤立したリソースを削除し、不足しているタグを修正します。これらの手順により、クラウド予算の予測可能性が高まり、十分に活用されていないインフラストラクチャを排除して運用効率を向上させることができます。

効果的なコスト配分（Cost Allocation）戦略を実現するには、タグを活用し、監視する必要があります。このプレイブックの目的は、タグ付け基準に準拠していないリソースを検出し、廃止されたサービスの調査に関するガイダンスを提供することです。

AWSが新しい機能、料金モデル、ユーザーインターフェースなどをリリースするにつれて、このような活動を実行するための具体的な手順は時間の経過とともに変化する可能性があります。このドキュメントが長期にわたって有用であり続けるよう、可能な限りAWSが提供する関連ドキュメントへのリンクを掲載しています。本書で提供する知見、手順、リソースを、AWSから直接提供される情報と組み合わせることで、FinOpsおよび使用量の最適化（Usage Optimization）に関連するこのアクションをより完全に理解できます。

### 本プレイブックの対象読者

本プレイブックは、主に組織にタグ付け基準が適用されていることを監視・確認したいFinOps実践者を対象としています。また、エンジニアが主体的にリソースをデプロイし、正しくタグ付けされているか確認したい場合にも活用できます。

## 前提条件

本プレイブックを効果的に活用するには、AWS Management Consoleへのアクセスが必要です。主に使用するサービスはAWS Configであり、該当するアカウントまたは組織全体で有効化されている必要があります。AWS Configは、構成情報の包括的なデータベースを生成するために、少なくとも24時間実行する必要があります。

このセットアップは、規定のクエリと手順を実行し、AWSリソースの正確な追跡と管理を確実にするために不可欠です。アカウントまたは組織でAWS Configが有効になっていない場合、内部データベースにアカウント内のすべてのリソースが登録されるまでに最大24時間かかることがあります。

[単一のアカウントで有効化](<https://docs.aws.amazon.com/config/latest/developerguide/1-click-setup.html>)するか、[AWS Organization全体で有効化](<https://docs.aws.amazon.com/organizations/latest/userguide/services-that-can-integrate-config.html>)できます。詳細については、AWSドキュメントのセットアップページを参照してください。

現在および将来のすべてのリソースを記録することをお勧めします。データ保持期間は業界の要件に応じて設定できますが、特に要件がない場合は、最小限の日数に設定できます。

アカウント内にバケットを新規作成するか、既存のバケットを使用できます。セットアップの詳細については、[ドキュメントページ](<https://docs.aws.amazon.com/config/latest/developerguide/gs-console.html>)を参照してください。

関与が必要な関係者：

  * FinOps実践者またはエンジニア：推進者（Driver）として情報収集を行い、エンジニアリングチーム、アカウント所有者、またはリソース所有者との議論を可能にし、対応が必要なリソースを特定します。
  * エンジニア、アカウント所有者、またはリソース所有者：決定者（Decider）として、指定されたリソースに対して必要なアクションを実行し、適切な対処を行います。
  * すべてのチームメンバー：推進者としてタグコンプライアンスへの対応手順を実行し、アカウントへの意識向上に貢献し、情報に基づいた意思決定を促進することで、タグコンプライアンスを確実にします。

### 必要な情報とリソース

#### 情報

  * 組織のタグ付け基準に関する知識
  * AWS Console：AWS Consoleの仕組みとアクセス方法に関する基本的な理解：[AWS マネジメントコンソールをはじめよう | AWS デベロッパーセンター](<https://aws.amazon.com/getting-started/hands-on/getting-started-with-aws-management-console/>)
  * AWS Configの有効化：アカウントまたは組織全体でAWS Configを有効化していること。
  * データベース生成の所要時間：AWS Configが構成情報の完全なデータベースを作成するには、少なくとも24時間必要です。

#### ツール、ユーティリティ、テンプレート

  * AWS Config：[AWS Config](<https://docs.aws.amazon.com/config/>)の仕組みとアクセス方法に関する基本的な理解。

## 本プレイブックの実行手順

### ステップ1：すべてのリソースタイプの収集（所要時間：10分）

アカウント所有者やリソース所有者とリソース最適化の可能性について議論するために、すべてのリソースの包括的なリストを収集します。

  * AWS Configコンソールに移動します。
  * 「高度なクエリ（Advanced Queries）」を選択し、「新しいクエリ（New Query）」をクリックします。
  * 以下のクエリを使用して、すべてのリソースタイプを一覧表示します。

```sql
SELECT resourceType GROUP BY resourceType
```

このクエリにより、すべてのリソースタイプが表示されます。結果をエクスポートし、任意のツールを使用して詳細な分析を行います。

### ステップ2：アカウント/リソース所有者との議論およびアクション（所要時間：30分）

収集した情報をリソース所有者と確認し、削除可能なリソースがあるかどうかを判断します。

以下の詳細クエリを使用して、特定のリソースタイプに関する詳細情報を取得します。
```sql
SELECT * WHERE resourceType = 'AWS::AppConfig::DeploymentStrategy'
```

得られた結果に基づき、リソース所有者と協力して必要なアクションを決定します。

### ステップ3：タグコンプライアンスの監視（所要時間：10分）

タグコンプライアンスを確実にし、タグが不足しているリソースを特定します。

  * AWS Configコンソールに移動し、「ルール（Rules）」を選択します。
  * 「ルールの追加（Add rule）」をクリックします。
  * 「AWS管理ルール（AWS Managed rules）」を選択し、「required-tags」を選んで「次へ（Next）」をクリックします。
    * **注意：** 1ルールあたり100リソースの制限があるため、すべてのリソースを監視対象として選択することはできません。最も関連性の高いリソースを選択してください。
  * 必要なタグキーを定義し、ルールを保存します。
  * コンプライアンスレポートを評価し、必要なタグが不足しているリソースを特定します。

#### 追加情報

タグ付けおよびラベル付け戦略の詳細については、[FinOpsのタグ付けとラベル付け戦略](<https://www.finops.org/wg/cloud-cost-allocation/#strategies>)を参照してください。

## 成果と成功指標

### 本プレイブック実行による主な成果

  * **未使用リソースの削除：** 使用されていないサービスは必ずしもクリーンアップされるとは限りません。アカウント内のすべてのリソースを確認することで、孤立したリソースをクリーンアップできます。
  * **タグコンプライアンスの測定：** タグコンプライアンスを評価するルールをデプロイすることで、必要なタグが依然として不足しているリソースを把握し、その進捗状況についてチームにフィードバックを提供できます。

### 成功指標

  * 環境内で**不足しているタグや誤ったタグを特定**できていること。
  * **財務管理の強化：** タグ付けの改善とリソース最適化により、クラウド支出の管理が強化され、予算の予測可能性が高まり、財務目標との整合性が向上します。
  * **運用効率の向上：** リソースの利用状況を実際のニーズに合わせることで、組織は運用効率を向上させ、十分に活用されていないリソースへの無駄な支出を回避できます。

### 例外と考慮事項

  * 数百以上のアカウントを持つ組織では、詳細な粒度が失われる可能性があります。そのような場合は、未使用リソースの特定とタグコンプライアンスを効果的に行うために、さらなる検討やツールの導入が必要になる場合があります。

### AWSリソース利用率の最適化に関するFinOpsの知見

#### リソース利用率がもたらす財務的影響の理解

リソース利用率がもたらす財務的影響を理解することは、クラウド支出を効果的に管理するために不可欠です。AWS Configは、構成や使用パターンの知見を提供し、非効率なリソース配分が行われている領域を明らかにします。これらのパターンを分析することで、組織は過剰プロビジョニングを特定し、それに応じてリソースを調整することで、大幅なコスト削減を実現できます。

##### コスト対使用量の分析

  * コスト配分レポートと実際の使用統計を定期的に比較レビューし、不一致を特定してコスト削減の機会を見つけます。
  * AWS Cost ExplorerおよびAWS Budgetsを使用して、これらの不一致をリアルタイムで監視および管理します。

##### 履歴データの活用

  * AWS Configの履歴データを活用して将来のニーズを予測し、過剰プロビジョニングを正確に防止します。
  * 過去のトレンドを分析して需要を予測し、リソース配分を先手を打って調整します。

##### コスト配分のための戦略的なリソースタグ付け

タグ付けは、部門、プロジェクト、またはサービス全体のクラウド支出の可視性を高める戦略的なツールです。適切なタグ付けプロトコルを確立することで、支出されたすべての資金が説明可能になり、正しく配分されます。これは、正確なチャージバック（Chargeback）およびショーバック（Showback）プロセスに不可欠です。

  * タグ付けのベストプラクティス
    * コストセンター（Cost Center）、プロジェクト、所有者、環境などの必須タグを含む、義務的なタグ付けガイドラインを実装します。
    * すべてのリソースで一貫したタグ付けを徹底し、クラウド支出の管理とレポート作成を簡素化します。
  * 自動タグ付けソリューション
    * AWS Tag EditorやAWS Service Catalogなどの自動化ソリューションを使用して、リソース作成時にタグ付けポリシーを強制します。
    * 自動化により、タグ未設定のリソースのリスクを軽減し、タグ付け基準への準拠を確実にします。

##### コンプライアンスとガバナンスのためのAWS Configの活用

AWS Configは、クラウド環境におけるコンプライアンスとガバナンスを維持するための強力なツールです。コンプライアンスルールを設定することで、組織はリソースの監査を自動化し、社内基準や規制基準を満たしていることを確認できます。

  * コンプライアンス監視
    * AWS Configを使用して、AWS環境全体の構成変更を継続的に監視および記録し、セキュリティポリシーや規制への準拠を確実にします。
    * カスタムルールを設定するか、AWS Configの管理ルールを使用して、コンプライアンス基準を自動的に強制します。
  * ガバナンスの自動化
    * AWS ConfigをAWS Lambdaと統合し、非準拠リソースに対する是正処置を自動化します。
    * AWS Configを使用してAWS CloudFormationテンプレートをトリガーし、コンプライアンス問題の自動修復を行います。

##### 協調的な最適化の取り組み

リソースの最適化は、IT、財務、およびビジネスユニットのステークホルダーが関与する協調的な取り組みであるべきです。連携することで、最適化の取り組みがビジネス目標と一致し、重要な業務に影響を与えないようにします。

  * 部門横断チーム
    * IT、財務、ビジネスユニットのメンバーを含む部門横断的なFinOpsチームを立ち上げ、クラウド支出とリソース最適化戦略を監督します。
    * チームメンバー間のコミュニケーションとコラボレーションを促進し、最適化の取り組みをビジネス目標に合わせます。
  * 定期的なレビューと調整
    * リソースの使用状況とコストレポートをレビューする定期的な会議をスケジュールし、現在のビジネスニーズに基づいてリソースのスケーリングに関する情報に基づいた意思決定を行えるようにします。
    * 変化するビジネス要件に適応し、コストを最適化するために、リソース配分戦略を継続的に改善します。
