**概要：**

データセンターにFinOpsを適用することで、組織は支出を受動的なコストセンターから戦略的なビジネスの推進力へと転換できます。データセンターのコストと使用量データをFOCUS™（FinOps Open Cost and Usage Specification）標準に従って構造化することで、組織は内部のコストディメンション（ラックID、サイト名など）をFOCUSの列（リージョン名やリソースIDなど）にマッピングできます。このデータを標準化することで、FinOps実践者は、経営幹部などのステークホルダーがパブリッククラウドとその他のテクノロジー支出の両方にわたる複数年の計画や投資について、より適切で統一された意思決定を行えるように支援します。

### なぜデータセンターにFinOpsが必要なのか

データセンターは、受動的なコストセンターからビジネスパフォーマンスの重要な推進力へと進化しています。FinOpsは、組織が以下のことを行えるフレームワークを提供します。

  * 財務的な監視を戦略的なインフラ計画に統合する。
  * 複数のプラットフォームにわたる財務および運用の可視性を統一する。
  * 経営幹部などのステークホルダーが、複数年の計画、投資、リスク、およびスケーリングに関して、より適切な意思決定を行えるようにする。

FinOpsを採用することで、組織は断片的なインフラレポートから、コストの透明性を戦略的目標に整合させる、データに基づいた包括的なモデルへと移行できます。

### データセンター向けFinOps

本ドキュメントは、データセンター向けのハイレベルでベンダーに依存しないFinOpsのガイダンスを提供し、FinOps実践者の役割の範囲、FinOpsフレームワークの適用、および関連する理論的・実践的な検討事項を説明します。FOCUSへの言及はありますが、詳細なデータレベルの情報は別途扱います。

### 前提条件

パブリッククラウドにおける[FinOpsフレームワーク](<https://www.finops.org/framework>)のドメインとケイパビリティをすでに理解していること、および『_[パート1：データセンター向けFinOps – FinOpsプラクティスプロファイル作成の背景](<https://www.finops.org/wg/finops-for-data-center-creating-a-finops-practice-profile/>)_』と『_[パート2：データセンター向けFinOps – FinOpsフレームワークの適用](<https://www.finops.org/wg/finops-for-data-center-applying-the-finops-framework/>)_』の内容と概念を熟知していることが前提条件となります。

### はじめに、および目的

[FinOpsスコープ](<http://finops.org/framework/scopes>)とは、テクノロジーの価値を最大化するためにFinOpsの適用を導く、プロダクト、コストセンター、環境などのビジネス構成要素に整合した、任意のテクノロジーカテゴリにおける支出の定義されたセグメントです。FinOpsスコープは、フレームワークの運用モデルを拡張し、テクノロジー支出の重複する領域を網羅します。これは、プラクティスが進化してパブリッククラウド以外の活動も含むようになるにつれて、特に重要になります。

『[_State of FinOps 2026 Report_](<https://data.finops.org/2025-report/>)』によると、FinOps実践者の48%が現在データセンターのコスト管理に従事しており、その割合は毎年増加しています。これらの傾向は、FinOpsがパブリッククラウドサービスを超えて、より広範なテクノロジー支出の領域にますます適用されていることを示唆しています。（最新情報については、[最新のState of FinOps調査](<http://data.finops.org>)の結果を参照してください。）

FinOps実践者は、[コアペルソナおよび関連ペルソナ](<http://finops.org/framework/personas>)と協力することで、従来の財務、調達、技術のサイロ化された組織文化から、計画、コスト分析、最適化をサポートする、より統合されたデータ駆動型のアプローチへと組織文化をシフトさせる支援ができます。

本書の目的は、データセンター向けのFinOpsスコープを探求し、既存のFinOps実践者がこの領域とFinOpsフレームワークの適用を理解できるように支援することです。

### データセンターの定義と特徴

「データセンター」とは、契約またはサービス契約を通じて、クライアントが直接所有または管理する施設から提供される非クラウドITサービスを説明するために使用される広範な用語です。データセンターのスコープには、組織のテクノロジーニーズをサポートする物理的および仮想的なインフラの計画、取得、運用、および最適化に関連する、すべてのテクノロジー関連の支出と意思決定活動が含まれます。

本データセンター向けFinOpsシリーズにおけるデータセンターの定義、プライベートクラウドに関する特徴や特別な考慮事項（固定資産にFinOps原則を適用することで従来のインフラ管理の強化をサポートするデータセンターのスコープへのアプローチなど）の詳細については、[『パート1：データセンター向けFinOps – FinOpsプラクティスプロファイル作成の背景』](https://www.finops.org/wg/finops-for-data-center-creating-a-finops-practice-profile/)を参照してください。

## データセンター向けFOCUSの概要

[FinOps Open Cost and Usage Specification（FOCUS）](<https://focus.finops.org>)は、FinOps Foundationが支援するオープンな技術仕様です。クラウド、SaaS、データセンター、または請求が発生するあらゆるテクノロジーサービスにわたって、一貫性のある詳細な請求データの構造を提供します。

クラウドプロバイダーや社内システムのいずれからであっても、FOCUS形式のデータセットを採用することで、組織はFinOpsプラクティスをより容易に適用できます。データ構造の一貫性により、複雑さが軽減され、価値実現までの時間が短縮され、ツールの導入が簡素化されます。

データセンターの所有者にとって、社内のコストと使用量データをFOCUS仕様にフォーマットすることは、テクノロジー資産全体にわたる統一されたビューを作成し、コスト、使用量、およびパフォーマンスに関する最適な意思決定を可能にします。

**FOCUSは、テクノロジーカテゴリ（データセンターなど）全体での標準化とスケールを可能にします：**

  * コストディメンションと使用量メトリクスの用語を標準化する
  * データソースに関係なく、KPIと測定基準を統一する
  * ツール、ダッシュボード、自動化のオンボーディングと統合を簡素化する
  * 正規化のオーバーヘッドを排除し、インサイトの獲得とアクションまでの時間を短縮する
  * 取り込みと処理を合理化し、データの品質と信頼性を向上させる
  * チーム、ツール、環境全体で共通のプロセスを使用し、一貫した採用とトレーニングを可能にする

## FOCUS：データセンター適用に向けた推奨列マッピング

以下は、データセンターのコストと使用量を管理する企業にとって特に有用な、FOCUS標準の主要な要素です。

| **列名** | **主な考慮事項** | **データセンターにおける有用性** |
|---|---|---|
| Billed Cost | 前提 → SKUレベル。組織は、Billed Cost（請求コスト）に他のデータセンターコストをどのように組み込むか、またそれがList Cost（リストコスト）とどのように異なるかを検討する必要がある。データセンターの配賦のために、ここに追加のコストを加えることができる。 | 検討済み |
| Billing Account ID | データセンターまたはデータセンター群を所有するP&L（損益）組織を識別するためのインデックスとして使用する必要がある。 | 検討済み |
| Billing Account Name | データセンター組織の命名目的に使用できる。 | 検討済み |
| Billing Currency | 請求通貨を表す。 | 検討済み |
| Billing Period End | 主な前提に基づく → データセンター内での関連するSKUの見積もりと配賦を表すために、OpEx（運営費）アプローチの導入を適切に考慮しながら、FOCUSのBillingPeriodを評価する必要がある。データセンター自体の請求/償却期間において考慮する必要がある。 | 検討済み |
| Billing Period Start | 主な前提に基づく → FOCUS | 検討済み |
| Charge Category | 主に使用量（Usage）。データセンターでは税金や修正が発生する可能性が低いため。 | 検討済み |
| Charge Description | テキスト | オプション |
| Charge Frequency | 主な前提に基づく → FOCUS | 検討済み |
| Charge Period Start | 使用量が発生した時点。減価償却される資本資産の使用量について、人為的にバッチ処理される可能性がある。 | 検討済み |
| Charge Period End | 使用量が発生した時点。減価償却される資本資産の使用量について、人為的にバッチ処理される可能性がある。 | 検討済み |
| Invoice Issuer | データセンターを所有またはリースしているエンティティの名前である可能性が高い。 | 検討済み |
| Provider | データセンターを所有またはリースしている会社である可能性が高いが、自社のデータセンター内の機器をリースしている組織である可能性もある。**注意：ProviderはFOCUSの将来のバージョンで非推奨となり、1.3まで使用可能。** | 検討済み |
| Publisher | テキスト。関連性がない可能性が高いが、他のProviderを通じて販売しているエンティティからの請求があることを示す場合がある。FOCUSのクラウド利用において、Invoice Issuer、Provider、Publisherはマーケットプレイスでの購入を説明するために組み合わせて使用されるため、データセンターの利用においてもこれらのシナリオを考慮する。 | 検討済み |
| Sub Account ID | データセンターのサービスグループ、または個々のデータセンターを識別するためのインデックスとして使用できる。 | オプション |
| Sub Account Name | データセンターのサービスグループの命名に使用できる。 | オプション |
| Contracted Cost | データセンターの要素のコストを交渉している場合、List Costとは異なる値がここに入る可能性がある。 | オプション |
| Effective Cost | 前提 → SKUレベル。割引を行っている場合、変動割引を考慮している場合、または減価償却を「前払いコミットメント」として扱っている場合、Effective Cost（実効コスト）はList Costから減額される可能性がある。そうでない場合はオプションとなる。 | オプション / 検討済み |
| List Cost | 定額の前提 | 検討済み |
| Contracted Unit Price | 前提 → SKUレベル | 検討済み |
| List Unit Price | SKUレベルの参照 | 検討済み |
| Pricing Category | この点は採用モデルに関連している。 | 検討済み |
| Pricing Quantity | 上記の考慮事項に関連している。 | 検討済み |
| Pricing Unit | 上記の考慮事項に関連している。 | 検討済み |
| Region ID | 物理的なデータセンターID（社内）である可能性が高い。 | 検討済み |
| Region Name | 物理的なデータセンター名（社内）である可能性が高い。 | 検討済み |
| Resource ID | データセンター内のSKUインデックス識別子。 | 検討済み |
| Resource Name | データセンター内のSKU名識別子。 | 検討済み |
| Resource Type | SKU表現レベル。 | 検討済み |
| Tags | 配賦/レポート/請求/チャージバック。 | 検討済み |
| SKU ID | 採用レイヤー。この構成要素は、特定のデータセンターが請求するSKUのカタログを定義するのに役立つ。 | 検討済み |
| SKU Meter | 上記の前提に関連している。 | 検討済み |
| SKU Price Details | 上記の前提に関連している。 | 検討済み |
| SKU Price ID | 上記の前提に関連している。 | 検討済み |
| Service Category | レイヤーの前提に関連、クロスプロバイダー。 | 検討済み |
| Service Name | レイヤーの前提に関連、クロスプロバイダー。 | 検討済み |
| Service Subcategory | レイヤーの前提に関連、クロスプロバイダー。 | 検討済み |
| Consumed Quantity | SKUの前提に関連している。 | 検討済み |
| Consumed Unit | SKUの前提に関連している。 | 検討済み |

### **除外を推奨する列：**

  * Availability Zone
  * Capacity Reservation ID
  * Capacity Reservation Status
  * Charge Class
  * すべての「Commitment Discounts」関連の列

_注意：Commitment Discount（コミットメント割引）関連の列の除外は、データセンターサービスの請求において、同様のタイプの割引やコミットメントの仕組みが機能していないことを前提としています。_

### **不足している推奨列：**

不足している列は、適切な場合に正式な議論と進行を行うために、要件としてFOCUSワーキンググループに正式に提起される予定です。

  * Site ID/Name：組織が個々のデータセンターを識別するためにRegion IDやSub-Account IDを使用しない場合、このような追加の列が必要になる場合があります。組織は、正規化されたレポートクエリを機能させるために、クラウド、SaaS、およびデータセンターのデータ間で「ロケーション」の扱いを正規化する方法を検討する必要があります。
  * Rack ID/Name：データセンター内の位置情報。
  * Asset Contract Number（セットアップ/更新ウェーブのグループ化の参照）：これはタグになる可能性が高いです。
  * Asset Tiering Class（ハードウェア使用状況の分類用）：これはタグになる可能性が高いです。
  * Linked_asset_id：他のアセットに依存しているアセットを考慮します。これはタグ値、または使用量に関連するものになる可能性があります。
  * Depreciation（減価償却）：Effective CostとList Costのメトリクスの差分で取得される可能性があります。

## データセンター向けFinOps KPI

このセクションでは、データセンターのハードウェアプロバイダーに関係なく、すべての組織が使用できるデータセンター向けFinOps KPIの一覧を提供します。

注意：データセンター専用ではありませんが、FinOps Foundationのウェブサイトには追加のFinOps KPIが掲載されており、その一部はデータセンター向けFinOpsにも適用できる場合があります。 – <http://finops.org/wg/finops-kpis/>

  * ハイブリッド環境全体におけるビジネスサービスあたりのコストの算出
  * リソース効率のユニットメトリクスの開発（例：保存されたGBあたりのコスト、仮想CPUあたりのコスト）
  * ビジネスユニットメトリクス（例：トランザクションあたりのコスト、テナントあたりのコスト）
  * データセンターのエネルギー効率（PUE）の測定と最適化
  * 調達：主要メトリクス：調達からプロビジョニングまでのタイムラグ（Procurement-to-Provisioning Lag Time）
  * コミットメント：主要メトリクス：コミットメント利用率（Commitment Utilization Rate）
  * CAPEX：主要メトリクス：CAPEX ROIおよびOPEX効率
  * ファシリティ：主要メトリクス：ファシリティ効率 ＝ IT機器電力 / 総ファシリティ電力 ※PUEの更新
  * 最適化：主要メトリクス：最適化ROI ＝ （コスト削減額 ＋ パフォーマンス向上） / 導入コスト
