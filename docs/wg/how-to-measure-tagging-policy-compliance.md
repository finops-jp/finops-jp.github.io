**概要:** FinOps実践者（FinOps Practitioners）は、クラウドリソースが策定済みの必須タグ付け基準にどの程度準拠しているかを評価することで、タグ付けポリシー準拠（Tagging Policy Compliance）を測定します。このプロセスでは、必要なキーと値を正しく保持しているリソースの数と、「タグ付け可能」なリソースの総数を比較します。単に「タグ未設定」を測る指標とは異なり、この計算では、自動化されたコスト配分（Cost Allocation）やガバナンスに必要な特定の戦略的メタデータ（Metadata）（例：Environment、CostCenter）の正確性と存在に焦点を当てます。

本プレイブックは、[組織のタグ付けポリシーに準拠しているクラウドリソースのコスト割合](<https://www.finops.org/wg/finops-kpis/?prod_kpis%5Bquery%5D=tagg#modal-kpi-9653>)を計算するプロセスをユーザーに案内することを目的としています。この計算では、タグ付け戦略に従ってタグ付けポリシーに準拠しているリソースのコストを、クラウドコストの総額と比較します。

**計算式**
[code] 
        (Total Cost of Tagging Policy Compliant Cloud Resources / Total Cost of Cloud Resources) x 100


[/code]

**注記:** すべてのCSP（クラウドサービスプロバイダー）のクラウドリソースにタグを付けられるわけではありません。タグ付け不可能なリソースが存在するため、この指標で100%を達成することは困難な目標です。組織の好みに応じて、計算式を以下のように変更することで、タグ付け不可能なCSPクラウドリソースを除外できます。
[code] 
        (Total Cost of Tagging Policy Compliant Cloud Resources / Total Cost of taggable Cloud Resources) x 100


[/code]

### 本プレイブックの対象読者

本プレイブックは、FinOps実践者、またはタグ未設定リソースのコスト割合の計算に関心があるすべての人が使用すべきです。

## 前提条件

  * 発生したコストをリソースおよび関連するタグにマッピングするためのCSP請求データへのアクセス権、およびCSPが提供するコスト管理・レポートツールの使用方法に関する知識
  * 策定済みの組織のタグ付けポリシー
  * 組織のポリシーで定義されているタグ付け要件の理解
  * 設定済みの組織のタグ付け準拠目標（任意）
  * タグやラベルを適切に維持するために定義・配布されたタグ付け戦略やプロセスを含む、タグとラベルの実装および使用方法に関する理解

### 関与が必要な担当者

  * FinOps実践者は、CSP請求データを評価し、発生したコストを各リソースに関連付けられたタグにマッピングします。これにより、タグ準拠リソースに関連するコストを活動の原動力として特定します。
  * 担当チーム（FinOpsガバナンスモデルに基づく）は、クラウドリソースが組織のタグ付けポリシーに準拠していることを確認します。これにより、活動の貢献要素として、タグ付けされたリソースのコスト割合を最大化します。
  * 担当チームまたは担当メンバー（FinOpsガバナンスモデルに基づく）は、タグ準拠リソースに関連するコストの割合が、活動の決定要素としてKPIの許容範囲内にあることを確認します。

### 必要な情報とリソース

#### 情報

  * 請求データ：特定の期間において、タグ付けポリシーに準拠しているクラウドリソースに関連するコスト
  * タグ付けポリシー：組織のタグ付け戦略に従って強制される必須タグの特定
  * タグ付け準拠目標：タグ付けポリシーに準拠しているクラウドリソースの割合

#### ツール、ユーティリティ、テンプレート

  * ダッシュボードソリューション：タグ付けの準拠状況を追跡するために組織が使用するツール
  * タグやラベルの準拠データおよび関連コストを取得するためのコスト管理用CSPコンソール（例：AWS Cost Explorer、Azure Cost Management、GCP Billing）

## Azureでの手順

### Azureのタグ準拠リソースコストの収集（5分）

  * Azureアカウントにログインし、「コストの管理と請求」セクションを開き、必要に応じて請求スコープを選択してから、「コスト分析」ページを開きます。
  * 「コスト分析」ページで以下を行います。
    * コストデータを抽出する期間を選択し、正しいスコープを設定します。
    * グラフの種類として「表」を選択し、必要に応じて「粒度」を設定します。推奨される粒度は「月次」です。
    * グループ化オプションで「タグ」を探して選択し、リストから「タグ名」を選択します。
  * 出力された表のタグ値を検証し、組織のポリシーに準拠していることを確認します。有効なタグ値に関連するコストを合算します。これがタグ準拠リソースのコストを表します。
  * 準拠状況を測定したいすべてのタグについて、このプロセスを繰り返します。

### Azureの総リソースコストの収集（5分）

  * Azureアカウントにログインし、「コストの管理と請求」セクションを開き、必要に応じて請求スコープを選択してから、「コスト分析」ページを開きます。
  * 「コスト分析」ページで、指定された期間におけるすべてのクラウドリソースの総コストを特定します。
    * コストデータを抽出する期間を選択し、正しいスコープを設定します。この期間がステップ1で選択したものと同じであることを確認してください。
    * グラフの種類として「表」を選択し、必要に応じて「粒度」を設定します。推奨される粒度は「月次」です。
    * グループ化オプションで「なし」を探して選択します。

以下の計算式を使用して、タグ付けポリシーに準拠しているAzureクラウドコストの割合を計算します。
[code] 
        (Total Cost of Tagging Policy Compliant Cloud Resources (Step 1) / Total Cost of Cloud Resources (Step 2)) x 100


[/code]

## AWSでの手順

### AWSのタグ準拠リソースコストの収集（5分）

  * AWSマネジメントコンソールにサインインし、Cost Explorerに移動します。
  * AWS Cost Explorerのダッシュボードで以下を行います。
    * コストデータを抽出する期間を選択し、希望する粒度を設定します。推奨される粒度は「月次」です。
    * フィルターの「タグ」で、リソースがタグ付けポリシーに準拠しているとみなされるために必要なタグキーを選択します。
    * タグ付けポリシーに準拠しているリソースのコストを特定するために、必須タグを持たないリソースをフィルターで除外します。これを行うには、フィルターオプションを使用して、ステップ1.b.iiで選択したタグキーに従ってタグを持たないリソースを除外します。
      * フィルターの選択したタグキーの下で、「タグキーなし: _tag_name_」を選択します。
      * 上部にある「除外（excludes）」オプションを選択します。
  * ドロップダウンリストのタグ値を検証し、組織のポリシーに準拠していることを確認します。このプロセスは、選択したタグ値が有効かつ意味のあるものであり、監視用のタグとして役に立たないランダムな値ではないことを確認するためのものです。タグキーに対して値が入力されているからといって、その値が組織のタグ付けポリシーに準拠しているとは限らず、文字のわずかな違いでも問題になる可能性があるため、ここでは細部への注意が重要です。合計値は、タグに準拠しているリソースのコストを表す必要があります。

### AWSの総リソースコストの収集（5分）

  * AWSマネジメントコンソールにサインインし、Cost Explorerに移動します。
  * AWS Cost Explorerのダッシュボードで以下を行います。
    * コストデータを抽出する期間を選択し、希望する粒度を設定します。推奨される粒度は「月次」です。この期間がステップ1で選択したものと同じであることを確認してください。
    * グループ化オプションで「なし」を探して選択します。

以下の計算式を使用して、タグ付けポリシーに準拠しているAWSクラウドコストの割合を計算します。

(Total Cost of Tagging Policy Compliant Cloud Resources (Step 1) / Total Cost of Cloud Resources (Step 2)) x 100

## GCPでの手順

### GCPのタグ未設定リソースコストの収集（5分）

  * Google Cloudコンソールにサインインして「お支払い」に移動し、「レポート」を選択して「お支払いレポート」ビューを開きます。請求先アカウントレベルの権限がある場合は、請求先アカウントにリンクされているすべてのプロジェクトのコストを表示できます。
  * GCPお支払いレポートビューで以下を行います。
    * コストデータを抽出する時間的集計を選択し、正しい粒度を設定します。推奨される粒度は「月次」です。
    * フィルターで「ラベルキー」を選択し、コストデータを収集するラベルを選択します（タグ付け準拠要件に従います）。
  * 選択したラベルにマークされている値を確認します。これがタグ付けポリシーに準拠しているリソースに関連するコストを表します。
  * ラベル値のドロップダウンリストのデータを検証し、組織のポリシーに準拠していることを確認します。これがタグ準拠リソースのコストを表します。

### GCPの総リソースコストの収集（5分）

  * Google Cloudコンソールにサインインして「お支払い」に移動し、「レポート」を選択して「お支払いレポート」ビューを開きます。請求先アカウントレベルの権限がある場合は、請求先アカウントにリンクされているすべてのプロジェクトのコストを表示できます。
  * GCPお支払いレポートビューで以下を行います。
    * コストデータを抽出する時間的集計を選択し、正しい粒度を設定します。この期間がステップ1で選択したものと同じであることを確認してください。
    * 指定された期間におけるすべてのリソースの総コストを特定します。

以下の計算式を使用して、タグ付けポリシーに準拠しているGCPクラウドコストの割合を計算します。

(Total Cost of Tagging Policy Compliant Cloud Resources (Step 1) / Total Cost of Cloud Resources (Step 2)) x 100

## 成果と成功の指標

### 本プレイブック実行による主な成果

  * 本プレイブックを実行する主な成果は、タグ付けポリシーに準拠しているクラウドリソースに関連するコストの割合を特定することです。タグ付け準拠率の目標レベルを設定している組織は、現在の準拠率と目標とのギャップを評価し、改善の機会を特定できます。
  * この割合により、クラウドリソースのタグ付け準拠レベルをより正確に把握できます。クラウドリソースのタグ付けポリシーへの準拠は、支出の正確な可視性を獲得し、最適化の機会を特定するために不可欠であるため、この情報はFinOpsにとって極めて重要です。
  * この割合は、チャージバックやショーバックのプロセスで使用されるタグに対する準拠状況を測定する場合、それらのプロセスに基づいて計算されたコストのチャージバックやショーバックの有効性やカバー率を示す指標にもなります。

### 成功の指標

  * 本プレイブックを正常に完了すると、GCP、Azure、またはAWSにおけるタグ準拠のCSPリソースコストの割合が決定されます。
  * タグ付けポリシーの準拠状況が望ましいレベルにあることを確認するために、このKPI計算を毎月1回実行することを推奨します。

### 例外と考慮事項

  * タグ付け戦略への準拠度は、組織の成熟度レベル（Maturity Model）によって異なります。成熟度レベルが高くなるほど、タグ準拠リソースのコスト割合も高くなることが期待されます。
  * 一部のクラウドリソースはタグ付け不可能であることを考慮すると、100%の達成は困難です。そのため、このシナリオに対応するための初期目標として、90%超の準拠を目指すことが考えられます。
  * タグ付け不可能なリソースの詳細については、各CSPのドキュメントを参照してください。
    * [Azureリソースのタグ サポート](<https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/tag-support>)
    * [AWS Resource Groups およびタグエディタで作成できるリソースタイプ](<https://docs.aws.amazon.com/ARG/latest/userguide/supported-resources.html#supported-resources-tagging-console>)
    * [GCPラベルのサポート対象サービス](<https://cloud.google.com/resource-manager/docs/labels-supported-services>)
