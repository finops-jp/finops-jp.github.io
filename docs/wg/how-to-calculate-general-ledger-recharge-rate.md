**概要:** 総勘定元帳（General Ledger: GL）リチャージ率は、組織の会計システムに記録されたクラウドの総支出額が、クラウドサービスプロバイダー（Cloud Service Provider: CSP）からの実際の請求額と一致しているかを確認するために使用するKPIです。FinOps実践者（FinOps Practitioner）は、特定の会計期間におけるアモルタイズコスト（Amortized costs）または非ブレンドコスト（Unblended costs）をクラウドコンソールから抽出し、財務システムに転記された仕訳入力（Journal entries）と照合する必要があります。完全な財務上の説明責任を果たすため、これら2つの数値の間に差異がある場合は、使用したソースデータや通貨換算方法を即座に調査する必要があります。このプレイブック（Playbook）を毎月定期的に実行することで、クラウドの変動費を従来の財務管理ワークフローに統合し、すべてのクラウド関連取引に対して信頼できる単一の記録を提供できます。

このプレイブックは、会計システムに仕訳として記録されたクラウドの総支出額が、対象月におけるCSP（AWS、Google Cloud、Azure、Oracle Cloud Infrastructureなど）のクラウド総支出額と等しいかを比較することにより、クラウド支出が組織の財務管理プロセスおよびシステムに統合されているかを確認する方法を案内します。

[請求とチャージバック](<https://www.finops.org/wg/finops-kpis/?prod_kpis%5BrefinementList%5D%5Bcapabilities.title%5D%5B0%5D=Invoicing%20%26%20Chargeback#modal-kpi-9663>)における総勘定元帳リチャージ率を計算すると、リチャージ率は100%になるはずです。  
具体的には、CSPネイティブ、サードパーティ製SaaS、または独自構築のソリューションのいずれであるかを問わず、クラウドコスト管理ツールに記録されたクラウド支出が、会計記録（別名：総勘定元帳）と一致したときにこの統合が実現します。

本プレイブックは、組織にとってどのメトリクスが正しいかを規定する決定的なガイドではありません。むしろ、クラウド財務管理のガバナンスを実行する方法についての推奨事項を提供するものです。また、共有コストの再配賦方法や、関連するプロダクト、コストセンター、ドメイン、ビジネスユニット、部門へのクロスチャージ（内部課金）の方法についてのガイダンスも提供しません。

本プレイブックは、Amazon Web Services（AWS）、Google Cloud（GCP）、Oracle Cloud Infrastructure（OCI）、Azure向けのプレイ（Play）を対象としています。

### 本プレイブックの対象読者

組織の会計プロセスおよびシステム（すなわち総勘定元帳）を通じて、クラウドコストをチャージバックする責任を持つすべての個人またはチーム。

## 前提条件

AWS Billing and Cost ManagementなどのCSPネイティブのコスト管理ツール、サードパーティ製のクラウドコスト管理ツール、または独自構築のソリューションへのアクセス権、および会計記録（別名：総勘定元帳）へのアクセス権または閲覧権限。

注意：複数のCSPから一貫した請求書とデータを取り込むには、[FOCUS](<https://focus.finops.org/>)標準を参照してください。

FinOps実践者は、クラウドコストデータと会計プロセスおよびシステムとの統合を促進するために、財務チームと調整できる権限を持つ必要があります。

FinOps実践者は、組織のコストデータセット（非ブレンドコスト、アモルタイズコスト、またはブレンドコスト（Blended cost））を把握している必要があります。どのビューを選択すべきかの判断については、[AWSコストデータセットの理解：チートシート](<https://aws.amazon.com/blogs/aws-cloud-financial-management/understanding-your-aws-cost-datasets-a-cheat-sheet/>)を参照してください。

### 関与が必要な関係者

  * 推進者（Driver）：FinOps実践者またはチームは、クラウドコストが完全かつ正確であること、確立されたポリシーに基づいて配分されていることを検証し、これらの値が会計システム（アプリケーション）を通じて確実にチャージバックされるようにする責任を負います*。 
    * 注意：*財務チームは、チャージバック額を会計システムに記録する責任を負います。

  * 貢献者（Contributor）：繰り返しになりますが、財務チームは会計システムにチャージバック額を記録する責任を負います。財務チームは、FinOps実践者またはチームが会計システム（アプリケーション）を通じてチャージバックプロセスを監視できるように、会計システムへの直接アクセス権を提供する場合があります。

## AWS、GCP、Azure、OCIでこのプレイを実行する手順

### ステップ1 – 準備 – 10分

  * FinOpsペルソナ（実践者）は、クラウドコンソール内の請求およびコスト管理モジュールにアクセスする必要があります。クラウドの請求書に対応する、通常1か月間の指定された期間のクラウドコストを算出します。
  * デフォルトの期間は12月1日から12月31日などの暦月ですが、組織によっては、11月27日から12月24日などの会計期間に基づく場合もあります。
  * 指定された期間の総コスト**と使用量の値をメモします（例：$72,184.58。「例外と考慮事項」セクションを参照）。

**組織は、総コストデータセットを非ブレンドコスト、アモルタイズコスト、またはブレンドコストとして表示できます。非ブレンドコストは現金主義会計に基づくコストを表し、アモルタイズコストは発生主義会計に基づくコストを表します。どのビューを選択すべきかの判断については、次の[AWSドキュメント](<https://aws.amazon.com/blogs/aws-cloud-financial-management/understanding-your-aws-cost-datasets-a-cheat-sheet/>)を参照してください。

**注意：** ほとんどの組織は非ブレンドコストデータセットを使用しています。

### ステップ2 – 計算 – 10分

この作業では、財務会計システム（別名：総勘定元帳）に転記されたクラウド支出額を検証します。会計システムへのアクセス権がある場合はFinOps実践者ペルソナが、そうでない場合は財務ペルソナがこの作業を担当します。

財務ペルソナがこれらの手順を実行する場合、FinOps実践者は指定された期間の総コストと使用量の値（例：$72,184.58）を財務ペルソナに提供して調整する必要があります。この金額が、指定された期間に会計システム（別名：総勘定元帳）に転記された金額と照合されます。

会計システム内で、勘定科目コード（名目コード）を照会するか、仕訳照会を実行して、転記された金額を取得します。会計システムに転記された金額（例：$72,184.58）をメモします。

クラウドコンソールと会計システムから取得した2つの値を使用して、総勘定元帳リチャージ率を算出します。

会計システムに仕訳として記録されたクラウドの総支出額 / AWSにおける当月のクラウド総支出額 × 100%

_例：$72,184.58 / $72,184.58 × 100% = 会計システムへのチャージ率100%_

**注意：** 上記の例は、クラウドサービスプロバイダーにおけるクラウド支出と会計システムにおけるクラウド支出の差がゼロであることを示しています。

## 成果と成功の指標

指定された期間のすべてのクラウド総コストと使用量の値が会計システム（別名：総勘定元帳）に転記されていることを確認するために、このプレイブックは毎月実行する必要があります（[機能的活動](<https://www.finops.org/framework/capabilities/chargeback/>)を参照）。

組織が暦月以外の会計期間で報告している場合は、11月27日から12月24日などの会計期間に基づいて実行することもできます。

成功の指標は、クラウドサービスプロバイダーにおけるクラウド支出と会計システムにおけるクラウド支出の差がゼロであることです。

クラウドサービスプロバイダーと会計システムの間のクラウド支出の差がゼロでない場合、すべてのクラウドコストと使用量の値が会計システムに転記されていないか、過剰に転記されていることを意味します。この原因について、さらなる調査が必要です。多くの場合、会計システムでの修正対応が必要になります。

### 本プレイブック実行による主な成果

  * 定義された成果として、エンドユーザーは、会計システムに仕訳として記録されたクラウドの総支出額が、CSPの記録（AWS、Google Cloud、Azure、Oracle Cloud Infrastructureなど）における同期間のクラウド総支出額と等しいかを判断できます。クラウドサービスプロバイダーにおけるクラウド支出と会計システムにおけるクラウド支出の差はゼロである必要があります。財務会計システムに仕訳として記録されたクラウドの総支出額 / Oracle Cloud Infrastructureにおける当月のクラウド総支出額 × 100%
  * クラウドサービスプロバイダーと会計システムの間のクラウド支出に差異がある場合、すなわち[総勘定元帳リチャージ率](<https://www.finops.org/wg/finops-kpis/?prod_kpis%5BrefinementList%5D%5Bcapabilities.title%5D%5B0%5D=Invoicing%20%26%20Chargeback#modal-kpi-9663>)が100%でない場合は、さらに調査する必要があります。考えられる是正アクションは以下の通りです。
    * 財務会計システム（別名：総勘定元帳）にクラウド支出額を転記した担当者に問い合わせ、プロセスがどのように実行されたか、および転記の作成に使用されたソースデータがどこから取得されたかを確認する。
    * 該当する期間のクラウドコストをCSPのコスト管理ツール内で再生成する。これにより、対象期間のクラウドコストの値が、以前に実行されたときから変更されていないかを確認する。
    * CSPのコスト管理ツール内に、指定された期間のクラウドコスト結果を歪めるような新しい追加フィルターが設定されていないかを確認する。

### 例外と考慮事項

組織が財務取引の記録に使用している動作通貨および報告通貨によっては、コストと使用量の値を報告通貨に換算する必要がある場合があります。

_例：英国で事業を運営し報告している場合、12月のコストと使用量の値である$72,184.58は、財務チームまたは財務部門が提供する為替レート（USDからGBPへ0.79354など）を使用して、英国ポンド（GBP）の£57,281.35に換算する必要があります。_

その後、会計システムに進み、勘定科目コード（名目コード）を照会するか、仕訳照会を実行すれば、転記された金額を取得できます。会計システムに転記された金額（例：£57,281.35）をメモします。

クラウドコンソールと会計システムから取得した2つの値を使用して、総勘定元帳リチャージ率を算出します。

会計システムに仕訳として記録されたクラウドの総支出額 / AWSにおける当月のクラウド総支出額 × 100%

_例：£57,281.35 / £57,281.35 × 100% = 会計システムへのチャージ率100%_
